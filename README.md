# BOM-App — دموی فارسی سیستم مدیریت BOM

نسخه اولیه مستقل از دیتابیس، ساخته‌شده با **React + Vite**. رابط فارسی RTL و داده‌های نمونه از فایل‌های JSON بارگذاری می‌شوند.

## شروع سریع در سیستم شخصی

```bash
npm install
npm run dev
```

پس از اجرا، آدرس نشان‌داده‌شده در ترمینال را باز کنید.

## راه‌اندازی GitHub Pages در مخزن BOM-App

1. محتوای **داخل پوشه `BOM-App`** فایل ZIP را در ریشه مخزن GitHub آپلود کنید؛ فایل `package.json` باید در ریشه Repo باشد.
2. اگر مخزن تازه است، شاخه اصلی را `main` بگذارید.
3. در GitHub به **Settings → Pages → Build and deployment** بروید و **Source: GitHub Actions** را انتخاب کنید.
4. فایل workflow موجود در `.github/workflows/deploy.yml` در هر Push به `main` سایت را Build و منتشر می‌کند.
5. پس از سبزشدن workflow در **Actions**، آدرس دمو از بخش Pages قابل مشاهده است.

> اگر هنگام آپلود با GitHub Web گزینه Hidden files در پوشه `.github` به‌درستی منتقل نشد، می‌توانید فایل workflow را به‌طور جداگانه ایجاد کنید یا مخزن را با Git آپلود کنید.

## ساختار داده

- `public/data/items.json`: بانک اقلام یکتا
- `public/data/suppliers.json`: تأمین‌کنندگان
- `public/data/quotations.json`: تاریخچه استعلام‌ها و قیمت‌ها
- `public/data/assemblies.json`: ماژول‌ها و سامانه‌ها
- `public/data/projects.json`: پروژه‌ها و BOM پروژه

## رفتار ذخیره‌سازی

GitHub Pages یک میزبان **ایستا** است و فایل‌های JSON موجود در مخزن را از مرورگر تغییر نمی‌دهد.

- اولین اجرا: داده‌های نمونه از `public/data/*.json` خوانده می‌شوند.
- هر تغییر: در `localStorage` همان مرورگر ذخیره می‌شود.
- انتقال داده: با «خروجی JSON» یک پشتیبان بگیرید و روی دستگاه دیگر از «ورود JSON» استفاده کنید.
- برای ویرایش داده‌های نمونه مشترک سایت، فایل‌های مخزن را اصلاح و دوباره Deploy کنید.
- **هشدار:** داده محرمانه یا قیمت واقعی را در مخزن عمومی یا دموی عمومی ذخیره نکنید.

## محدودیت‌ها و نکات مهم دمو

- نسخه `0.1` نمونه کاربردی برای بررسی جریان کار است، نه سامانه عملیاتی یا حسابداری.
- قیمت‌ها و مشخصات نمونه ساختگی/آزمایشی‌اند.
- درخت BOM بازگشتی و انتخاب قیمت به تفکیک مسیر وقوع پیاده شده است.
- `Reference` به ساختار یکسان اشاره می‌کند. `Duplicate` تعریف مستقلی می‌سازد؛ **برای سفارشی‌سازی ساختارهای کپی‌شده از بخش افزودن جزء استفاده کنید**.
- قیمت جدید پیشنهادی از آخرین استعلام ثبت‌شده قلم گرفته می‌شود؛ در نسخه عملیاتی باید اعتبار، MOQ، ارز، شرایط حمل و سیاست انتخاب تأمین‌کننده کنترل شوند.
- هزینه نمونه فقط مجموع قیمت اقلام است؛ خدمات، هزینه ساخت، مالیات، حمل، نرخ تبدیل ارز و قیمت‌گذاری Fixed هنوز پیاده نشده‌اند.
- تاریخچه برآورد و Baseline در JSON ذخیره می‌شود؛ قابلیت ویرایش Baseline در رابط وجود ندارد، ولی این نسخه امنیت سروری و تضمین تغییرناپذیری واقعی ندارد.
- یک پروژه فعلاً با شیوه ساده‌سازی‌شده قیمت‌گذاری از روی مسیر BOM کار می‌کند؛ با ساختارهای بسیار پیچیده و تغییر نسخه مرجع، به مدل Usage Instance و Migration قیمت نیاز است.
- درخواست استعلام و ارجاع کار در نسخه‌های بعدی اضافه می‌شود.

## فناوری و ساختار

`React 19`، `Vite 6`، `lucide-react` و CSS اختصاصی RTL، بدون Backend و دیتابیس.

مجوز: نمونه داخلی آزمایشی؛ پیش از استفاده تجاری، شرایط مجوز وابستگی‌ها را بررسی کنید.


## نسخه 0.2: نمایش تعداد در BOM

در درخت پروژه، ستون «تعداد در والد» قابل ویرایش است و «تعداد کل» حاصل‌ضرب تعداد در تمام سطوح است. هزینه هر ردیف نیز از تعداد کل محاسبه می‌شود. در کتابخانه ماژول‌ها و سامانه‌ها، جزئیات اجزا و تعداد مستقیم آن‌ها قابل مشاهده است. تغییر تعداد جزء در یک Reference ساختار مشترک را تغییر می‌دهد و بر همه استفاده‌های آن ساختار مؤثر است.

برای بازگردانی داده‌های نسخه جدید اگر داده‌های قبلی در مرورگر حفظ شده‌اند، از منوی تاریخچه «بازگردانی داده نمونه» استفاده کنید (تغییرات ذخیره‌شده مرورگر حذف می‌شوند).
